## 2. Broken or risky code (storefront)

Observed locally (production build, 390 px) and on live:
- **All static routes bail out to client-side rendering [live + local]** — verified with curl on live (`/faq`, `/blogs`, `/story`, `/reviews` all carry the bailout marker) and locally on the production build (8 routes). `app/providers.tsx:11-19` `AppBridgeWrapper` calls `useSearchParams()` for nothing (reads `host` and discards it, a leftover from Shopify App Bridge), and the `<Suspense fallback={null}>` at `:70-72` encloses trackers, header, `main` and footer. Under Next 14 rules a `useSearchParams()` read during static prerender makes everything up to the nearest Suspense boundary client-only. Browsers recover after hydration (live `/collections` shows its 10 collections after ~1 s), crawlers get nothing, `priority` image preloads never reach the HTML, and LCP waits for the full JS download + RSC refetch. **Fix:** delete `AppBridgeWrapper` and its inner `Suspense` (design-preserving). `app/cart/page.tsx` additionally needs its own `<Suspense>` around the `useSearchParams()` consumer.
- **Shopify fetches are `cache: 'no-store'` at runtime** (`lib/shopify-admin.ts:52,128`, `lib/shopify-client.ts:228`; only build time uses `force-cache`), and `unstable_cache` is used nowhere; `revalidateTag('homepage')` in `lib/storefrontRefresh.ts:34` is a no-op because nothing is tagged. Effect: pages that declare `revalidate` either render on every request or fail revalidation with Next's "static to dynamic at runtime" error — the latter is the live `sitemap.xml` 500 (next bullet). The only caching is per-process `Map`s (`pageCache` 5 min, `requestCache` 3 min, `gidCache` 1 h) that never evict and do not dedupe concurrent misses.
- **`sitemap.xml` → 500 on live**, 200 locally. Local `next start` serves the build-time static copy; the live server has passed the 3600 s revalidation window and the regeneration hits the same `no-store`-inside-static conflict (Next 14 "static to dynamic at runtime" → the pages-router `_error` 500 page, which is exactly what live returns). Secondary suspects if that is fixed and it still 500s: `fetchStorefrontCatalog` paginating all 435 products on each regeneration, or the `prisma.policy` import. **Fix (needs approval, 2 lines):** `export const dynamic = 'force-dynamic'` in `app/sitemap.ts` (and drop `revalidate`), or better, stop using `cache: 'no-store'` in the Shopify helpers for GET reads and rely on the existing in-memory `pageCache` + `revalidate` (also fixes finding 2).
- **Soft 404s everywhere [live]**: `/products/<missing>` and `/collections/<missing>` return **HTTP 200** with `noindex` because `loading.tsx` streams the shell before `notFound()` runs. Only truly unmatched routes return 404. 7 sitemap collections are in this state (list in §0). Fix: generate metadata/`notFound()` before the Suspense boundary, or remove the per-segment `loading.tsx` for those routes, plus delete the dead handles from `app/sitemap.ts:30-62` and the two redirects in `next.config.mjs:142-151` (or recreate those collections in Shopify).
- **Hero video requests a file that does not exist**: `/zb-video-heroo.mp4` → 404 on every home load (local; on live the MP4 source is the Shopify CDN URL from CMS, the WEBM fallback is `/zb-video-heroo.webm`, 3.3 MB). `components/HeroVideo.tsx` falls back to a local MP4 path that is not in `public/`.
- **Doubled brand suffix in `<title>`** on `/collections`, `/search`, `/products/<missing>`, `/faq`, `/gallery`, `/reviews`: pages set `title: "… | Zica Bella®"` and the root template appends `| Zica Bella® | Luxury Indian Streetwear` again (`app/layout.tsx:63-66`).
- **Canonical inheritance bug [live]**: `/collections` (index) and the product-not-found page emit `<link rel="canonical" href="https://zicabella.com">` (the root `alternates.canonical`) — the index page should canonicalise to itself.
- **Live `robots.txt` points `Host:` and `Sitemap:` at `https://app.zicabella.com`** because production has `NEXT_PUBLIC_APP_URL=https://app.zicabella.com` while `app/sitemap.ts` and `app/robots.ts` use that variable (the rest of the site uses `NEXT_PUBLIC_SITE_URL`). Google treats a cross-host sitemap as invalid. Fix: use `NEXT_PUBLIC_SITE_URL` in both files (one-line each) — server env must not change.
- **`/policies/[handle]` crashed locally** (`toISOString` on undefined) — an artefact of the DB mock returning `{id:'mock_id'…}` for `findUnique`; cannot reproduce on live (page renders). Listed for completeness; the mock in `lib/db.ts:23-57` returns a fake object instead of `null` and will mask bugs in any dev setup using `ALLOW_DB_MOCK`.
- **Client-side data fetching on every page view [live]**: 11 XHRs after hydration on a product page — `/api/auth/session`, `/api/analytics/track`, `/api/shopify/collections?location=header`, `/api/global-store/config`, `/api/wishlist`, `/api/cart/me`, `/api/customers/me/default-address`, `POST /api/cart/sync` (even with an empty anonymous cart), `/api/meta/event`, `/api/snap/event`, `/api/openai-ads/event`, plus on PDP `/api/mood-board` and `/api/whatsapp-events/track`. Header collections and global-store config are static data that should be server props; wishlist/cart-me/default-address are pointless for anonymous users. On the 404 page the whole set fires twice (not-found boundary remounts the layout client tree).
- **Middleware does a self-HTTP round trip on every admin API request** (`middleware.ts:399-417`) that always fails (`Unexpected token '<'` seen in the local log) and falls back to the JWT. Dashboard only, but it runs in the same process as the storefront.
- **Dead code**: `CheckoutWebView`, `OrderSuccess`, `/api/shopify/checkout` (never reached: `checkoutUrl` is never set in `CartDrawer`, `app/cart`, PDP), `lib/metaPixel.ts:83 pageview()`, `adminGtmId` in layout, `lib/gtag.ts GA_MEASUREMENT_ID` (never read), `components/ScannerComponent`, `Globe3D`/`ThreeDLogo` (confirm usage in Phase 2), `lib/shopify-image-loader.ts` (the `.js` twin is the one in `next.config`).
- **Console**: zero JS exceptions on the storefront pages locally apart from the expected Shopify-401 server-component error. On **live** the console shows CSP violations: a GTM-injected tag tries `https://signals.birch.click/...` and an AWS ECS endpoint (blocked by `connect-src`), and something frames `https://www.facebook.com/` (blocked by `frame-src`). Either that tag was removed from the published container since (it had no tags when fetched) or it is injected by a browser extension; verify in Chrome with GTM preview. If a tag is meant to run there, the CSP must list it.
- **`/gallery` can never show content for visitors**: `app/gallery/GalleryClient.tsx` fetches `/api/web-store/gallery`, which the middleware gates behind an admin session (`/api/web-store*`), so anonymous users get **403** and the page always renders "Gallery Archive Empty" (reproduced locally; the same route list in `middleware.ts` only exempts `banners`). Fix: exempt `/api/web-store/gallery` GET like `banners`, or read the gallery server-side in `app/gallery/page.tsx`.
- Error boundaries exist at root, `/checkout`, `/search`, `/products/[id]`, `/collections/[handle]`; none for `/cart`, `/blogs`, `/policies`, `/orders/*`, `/profile` (a server error there shows the generic root boundary and unmounts the whole shell).

## 5. Security basics

Verified in source (values never printed). The security agent's full route table is in `scratchpad/routes.tsv`.

**Critical — fix before any marketing spend goes up**
- S1 `POST /api/razorpay/refund` and `/api/razorpay/capture-payment`: **no auth** (middleware explicitly lets all of `/api/razorpay/*` through, `middleware.ts:116-122`). Anyone can refund any payment id. `/api/razorpay/payments` lists the last 100 payments with names/emails.
- S2 OTP login (`app/api/auth/[...nextauth]/options.ts:219-238, 314-326` and `app/api/auth/mobile-verify/route.ts:115-146`): phone is `slice(-10)` with no length check and looked up with `phone: { contains: normalizedPhone }`. An empty phone + the attacker's own OTP matches every row → logs into another customer. No per-phone brute-force lockout on the web provider.
- S3 `app/api/app/profile/route.ts:28-130`: GET/PATCH accept **any bearer ≥ 5 chars** and a hardcoded admin-bypass literal; returns/edits any customer by phone/email/id → account takeover (change phone, then OTP in).
- S4 `app/api/checkout/complete/route.ts:330-434`: merges any existing customer whose phone equals the **editable** delivery phone into the buyer (orders, addresses, wallet, carts reassigned). Reachable without a session.
- S5 Unauthenticated PII/order reads: `/api/app/orders` (`?all=true` dumps everything), `/api/orders/history`, `/api/portal/orders`, `/api/portal/login` (no password check), `/api/app/customers/addresses`, `/api/email/customers`, `/api/mail/contacts`, `/api/shopify/customers`, `/api/mail/inbox` (company IMAP), `/api/whatsapp/chat/*`, `/api/support/tickets` (admin view via forged `Referer`), `GET /api/orders/{ZB-number}/confirmation?bypass_auth=true` (sequential order numbers, < 24 h).
- S6 Unauthenticated writes: `/api/checkout/cancel` (cancels/overwrites any order incl. paid), `/api/shopify/variants/[id]` & `products/[id]` PATCH (price/SKU), `/api/shopify/inventory/adjust`, `/api/inventory`, `/api/shopify/sync`, `/api/shopify/auth/callback` (overwrites the shop token), `/api/marketing/send-campaign`, `/api/email/*`, `/api/mail/send`, `/api/notifications/send-manual`, `/api/send-notification`, `/api/whatsapp/chat/messages` POST, `/api/email/templates` DELETE (`deleteMany({})`), `/api/automations/[workflow]` (runs LLM tools, no `CRON_SECRET` check), `/api/seed-blogs`.

**High**
- H1 `requireAuth()` (`lib/auth/rbac.ts:18`) only checks a session exists → any OTP customer reaches `/api/app/customers` (list/create Shopify customers), `/api/workdrive/*`, `/api/whatsapp/chat/{media,upload}`.
- H2 Debug routes public: `/api/debug/db-info` (DB host/port), `db`, `db2`, `shop-inspect`, `featured`, `shopify-check`.
